# MIDI sequencing and instruments v1

Document manifest14 / `midi-instruments-v1` is deliberate, including an empty newly-created MIDI Track. Historical reserved MIDI metadata does not itself upgrade older files. Musical clips and instruments belong to their typed MIDI Track; audio clips cannot be moved onto it. Instrument precedes Track inserts, Group routing and Master. One collapsed automation lane per processable owner remains Volume-first. Native sampler Gain and Tuning use prepared project automation; hosted Instrument targets are visible read-only until scheduling/identity are separately qualified.

## Timeline and editing

Constant tempo 20–300 BPM, numerator 1–16, denominator2/4/8/16. No tempo map in this increment. Tick resolution is 9,600,000 per quarter; conversions round absolute project sample positions rather than accumulating block error. Each clip/note/controller has a stable ID. Independent copies rekey events/articulation identities; untouched split fragments preserve a source origin and tie identity so compilation joins their continuous history. Note and controller edits intentionally end that continuation. Musical overlap is allowed. Sustain, bend, program and CC data remain clip-scoped. Unmatched trim starts chase active notes/controllers; loop/clip ends release their owned notes and reset owned sustain/bend. Standard shared-channel controller semantics apply where overlapping clips use the same channel.

Piano roll is contextual in Edit, with Select/Draw/Erase, note-length drag, velocity lane, CC64/bend/CC1 lane, snap/zoom, quantize strength, transpose/velocity and copy/paste. Command-D duplicates timeline clips, Command-E splits, Delete removes selection. Note arrows transpose/nudge; Option-Up/Down adjusts velocity. Existing Audio canvas/fades and Perform remain separate.

## Native sampler

Referenced original/range, SHA-256 and explicit physical input/declared-role mapping; source originals are never moved or rewritten. Eight alternates maximum; deterministic round robin or MIDI program chooses an alternate. 32 bounded voices maximum; steal oldest released voice, otherwise oldest voice. Linear interpolation uses source/project rate, note/root/tuning and per-channel bend. Velocity scales amplitude. Linear ADSR is evaluated per sample; release starts at current envelope level. CC 7/11 and sustain 64 apply per channel. Loop and one-shot are mutually exclusive. CC120 and transport resets clear voices; note-offs release them. Settings and decoding are prepared off the device callback, at most 8Mi floats per source and 64Mi per project. Gain/tuning changes can affect sustained voices; envelope stage lengths are established on stage entry. Source stamp verification runs on the graph producer.

## CoreMIDI capture and monitoring

CoreMIDI MIDI1 packets retain native host timestamps. The callback parses bounded short messages and publishes plain packets into an 8192-entry SPSC queue; it performs no file/database I/O, loading or graph construction. System realtime/SysEx are ignored. A single device and channel filter feeds up to 16 armed owners per pass. Arm and monitoring are transient and reopen off. A pass contains at most the remaining 8192-design-event budget divided among owners; overflow/capacity exhaustion is incomplete, never silently accepted.

The existing output callback publishes host time, source frame, source rate and generation through the shared input timeline clock. The graph producer maps acquisition time to that clock and places monitored events at the first unrendered input frame when their desired frame is already prepared. The recording stores both acquisition and **applied audible project frame**; `lateEvents` / `maxLateFrames` expose the extra scheduling delay. This bounded producer-lookahead policy is not a calibrated zero-latency live-MIDI promise. Recorded clips use applied frames for audible/offline agreement. Unmonitored recording uses acquisition frames. Do not infer physical MIDI/round-trip latency from controlled clocks or owned virtual input.

MIDI seeks always prepare from project frame zero on the cancellable graph worker. The ordinary short effect warmup is insufficient to reconstruct held voices, sample positions and sustain. Long MIDI designs can therefore take longer to prepare; Stop cancels. Audio-only designs retain their existing approximate short-history live seek and deliberate Accurate Audition path. No second clock is introduced.

Recording uses the shared design transport and a temporary long graph range; Audio input and Perform automation recording are mutually distinct modes. Stop gates the acknowledged shared-clock boundary, pairs note offs (including zero-velocity note-on), retains release velocity, and closes remaining held notes at the boundary. Seek, Undo and topology edits require stopping MIDI capture. Monitoring panic clears held voices on input reconfiguration/disconnect and mute/solo changes. A playback/helper/device fault retains an incomplete pass. No callback persists events.

Version 1 `.midi-partial.json` journals contain bounded raw packet provenance, IDs/context, acquisition/applied frames, timing, checkpoint boundary and payload SHA-256. Worker checkpoint staging flushes/fsyncs before atomic rename and directory sync. Stop publishes a complete marker before clips are adopted in one Undo operation. Cancel/incomplete checkpoints remain in place and require deliberate Recovery from the Instrument menu. Recovery validates digest, version, bounds and context. Retained data is not labelled inserted unless current-document validation and actual retention succeed. A digest detects later content changes; it is not authentication against a malicious writer replacing both payload and digest.

## Isolated hosted Instruments

Dedicated `midi-instrument-v1` purpose on exactly one VST3/AUv2 processor. Ordinary effect racks keep effect classification and reject MIDI input. Instrument negotiation requires the actual instrument descriptor, acceptsMidi, no MIDI-only processor, all audio inputs/auxiliary outputs disabled and exact main output roles. Unsupported layouts fail without conversion. Purpose survives both hosted-rack and ordered-chain serialization.

VersionSPR4 bounded exchange carries up to 16,416 short events with offsets in the actual ≤512-frame block, project input frame, tempo and signature. Host playhead reports constant-tempo PPQ and project samples. Existing supervised process deadlines, binary fingerprint checks, fixed-state/frozen isolation, retained native GUI and coherent state/program/parameter capture apply. Instrument latency contributes before Track insert latency and shared graph PDC. Release/effect tails share the render contract; native live controls never load plugin code into the app/device callback. Reset sends sustain-off/all-sound-off/all-notes-off before processor reset. Native GUI is owned by the retained isolated instance used for live PCM. External Instrument automation remains read-only. No VST2/AUv3 or universal vendor claims.

## Takes and output

New MIDI frozen recipes use version5 / `midi-instrument-takes-v1`, capturing immutable score, tempo, Instrument identity/state, referenced sampler sources/hashes and the existing Track/Group/Master graph. Recipe 1–4 encoding/hashes remain unchanged. Native live/offline use the same scheduler and sampler; hosted output uses the existing single authoritative float pass for metering/normalization/delivery. Monitoring remains independent of export. Source/output paths and existing Resolve-referenced finalized WAVs remain durable.

## Live responsiveness correction (2026-11-22)

Untouched ordinary split fragments compile as one articulation within their stable track/origin and unchanged note/controller payload, requiring both timeline and source-offset adjacency. Interleaving other tracks or independent clips cannot break that continuation. Changed contents and deliberately separated fragments compile independently. Serialized project/recipe identities are unchanged.

Active connected MIDI monitoring uses callback-aware producer lookahead capped at the existing1536-frame target, with a12ms safety floor plus callback frames,256 minimum. The safety floor grows with observed producer maximum. Non-MIDI Library/audio production retains1536. This bounded policy reduces some virtual acquisition→applied scheduling delays; it does not qualify a physical keyboard or DAC/acoustic latency. Larger buffers and high rates can retain the cap and its prior limitation.

`MidiInputService::status().schedulingLatency` reports event count,8192-event bounded window, p50/p95/p99 and maximum acquisition→applied milliseconds. Source timestamps and actual applied frames remain separately journaled. Invalid clocks defer scheduling; stale/overflow/panic handling remains fail-closed. Telemetry sorting and journals run off the audio callback. See `COLLECTIONS_STAGE_A_REPORT.md` for paired controlled measurements, rejected6ms pilot and separate native-device evidence.
