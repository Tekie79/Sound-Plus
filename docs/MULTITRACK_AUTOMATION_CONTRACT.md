# Multitrack Edit / project automation v1 — implementation contract

Implemented contract. Executed evidence and open qualifications are recorded in MULTITRACK_REPORT.md; model code alone is not UI/audio acceptance.

## Identity and compatibility

Manifest11 / `multitrack-automation-v1` adds explicit Track IDs, clip-to-track references, organizational parents, independent output-bus routing and automation. Audio clips continue to store source identity, trims, placement, fades, rate, pools/locks and their explicit compatibility source-stage chain. Existing layer IDs become clip IDs; deterministic `track-<clipID>` identities initially give each legacy clip one Audio Track. Source gain/pan, source-stage effects before routing, source pool choice and Perform references are not moved or rehashed. Legacy documents can remain in their original representation until the first multitrack action materializes this equivalent structure. Historical take recipes retain their exact encoding and hashes.

New tracks sum independently processed clips, apply their own chain once on the declared track bus, then track volume/pan/spatial output routing. Routed Group Buses sum incoming tracks and apply their chain once; Master processes the final sum once. The same ordered path is used for audition and export. Overlapping clips sum; no implicit comp or crossfade. Legacy source-stage processors remain independent per clip, including their effect history/tails; a split/copied compatibility clip gets a distinct processor identity. Source files remain referenced in place.

Audio and MIDI-instrument are distinct types. Only Audio, Folder and Group creation are exposed until actual MIDI scheduling/instrument processing is delivered. MIDI's dedicated Instrument identity/state slot is separate from audio inserts, before the audio chain. A serialized future instrument is not runnable support. Master is the unique root bus. Folder parents can nest, collapse, reorder and unwrap on deletion. Non-folder deletion removes its clips; deleting a Group with incoming routes requires explicit rerouting. All operations are undoable. Both parent and output graphs reject cycles and missing/wrong-kind references.

Folder mute gates descendants without rewriting local flags; folder solo includes descendants. Group routing and organizational ancestry are distinct. Group solo includes routed inputs; neither reparenting nor collapsing changes output routes or processing.

## One lane and stable targets

Each processable track and Master owns one lane, initially collapsed with Volume selected. One searchable registry selects the displayed curve. Curve read, displayed target and Touch-armed target are independent. Every target persists under its owner track plus stable instance/parameter ID. Insert display names and order do not identify targets. Missing/deleted targets remain unresolved; Undo/relink may restore the same identity, never select a sibling. Organizational folders have no lane or audio chain.

Each read-enabled curve is evaluated even when hidden or collapsed. The base value applies when there is no enabled curve. Before the first stored point use the base, after the last hold its value. The first edit creates project-start/project-end base anchors so it does not alter unrelated portions of the project. Linear segments respect target scale (logarithmic Hz/time where appropriate); discrete values use hold. Times are integer project frames. Clip motion leaves project automation fixed; clip-relative/follow automation is a later explicit policy.

Volume is scheduled per sample. Supported native effect/pan/spatial controls use anchored32-frame segments, split at exact keyframe boundaries, with existing DSP smoothing. Scheduling uses each stage's input clock and reported-latency prefix; reported latency is not creative delay. External plugin/instrument targets may appear as non-writable registry entries until a separate validated scheduling contract exists. No universal sample-accurate third-party automation is promised.

Touch is supported only for validated native targets. A gesture captures its original target and curve at pointer-down, replaces only its written time slice, returns to the underlying curve over100ms and commits one undoable pass. Selecting another target cannot redirect it. Read curves are absolute parameter values; where a Perform mapping addresses the same parameter, the enabled automation curve is final authority, not a second gain multiplication. Distinct clip-stage Perform controls and post-sum Track controls compose at their explicit stages.

Immutable take recipe4 freezes tracks/clips/automation alongside source/plugin provenance. Existing Perform XY/macros remain the current four-assignment event contract; selecting a frozen take cannot inject new automation or native state. Snapshot/segment compilation, graph creation, JSON and file/database/state work occur outside the device callback.

## Subsequent increments (not decorative controls)

- Audio Record: input selection, arm, optional monitoring/meters; original recoverable audio written into a new clip; sample/latency alignment; safe finalization and recovery.
- MIDI Record/Instruments: timed notes/controllers, dedicated Instrument slot, native sampler and qualified external instruments, piano-roll/velocity/CC editing, note-off safety, state recall and exact output-bus negotiation.
- Perform pads: Pad A plus adjacent + creates up to four independent A–D tabs on one timeline; tab selection does not solo. Per-pad mute/solo/level and automation overdubs; recording B preserves A. Record stores automation, Render creates audio. Define whether solo/mute affect capture or audition explicitly before implementation.
- External parameter automation: qualified stable-ID/sample-timed event scheduling beyond frozen starting state.
- Automation: Latch, Write, Trim, Preview/Punch, loop/punch, Bézier/freehand, thinning, clip-relative automation and MIDI Learn.
- Product roadmap: nested collections/favorites and Designer browsing; precise Find Similar event refinement; expanded native EQ/dynamics/delay/reverb/creative effects; optional external AI providers; VST2/AUv3 qualification; portability and Resolve integration.

OldSkoolVerb custom input, native receiver drag, human listening and physical surround remain separate open qualifications. Preserve the finalized WAV references used by existing Resolve QA projects.

## Editor commands and accuracy limits

The Add track menu materializes the compatible editable live mix and creates Audio, Folder or Group owners. This is a deliberate live-edit boundary; loading or auditioning an old document alone never rewrites its frozen recipes. The old canvas remains available for non-materialized live documents. Empty tracks have their own selection, name, colour, mute/solo, base-volume slider and insert owner. Double-click a header name and press Return to rename. Drag header space to reorder; drag a row's bottom edge for height. Track options separate Folder membership, Audio output and named Track bus. Delete unwraps a folder; deleting a routed Group is rejected until its inputs are rerouted.

In the new canvas: drag clip body to move, including across Audio Tracks; Option-drag copies to an independent clip/processor identity; Shift-Option-drag slips source. Shift selects multiple clips. Drag clip edges for trim, the gain line for gain (Control is fine), and fixed corner fade markers for duration. Double-click the curve for custom fade points, drag points to reshape, Option-click a point to remove it, and right-click a corner for the retained shape presets. Shift addresses OUT when small corner handles overlap. Command bypasses snap. Command-E splits at the playhead; Command-D duplicates; Delete removes the selected clips (or the selected empty Track when no clips are selected). Existing Library audition, toolbar transport, markers, accurate audition and forward-grain preview stay available. Project automation does not move with a clip. Moving a compatibility source-stage processor to another Track leaves its original-owner curve unresolved; returning the clip restores the original binding. A copied processor never inherits another instance's automation accidentally.

In an expanded automation lane: double-click empty curve space to add; click/Shift-click or drag an empty rectangle to select points; drag selected points to change time/value. Command-A/C/V selects/copies/pastes; paste anchors the earliest copied point to the project playhead and requires matching units. Delete removes selected points. Up/Down offsets their values by one percent of the real-unit range. Return or the context menu edits the first selected point numerically without deleting the other selected points. The context menu sets selected segments to Linear or Hold. Command bypasses snap while moving/adding. Escape cancels the current gesture; changing focus completes it. Each completed pointer/Touch gesture makes one Undo item.

The selector groups Track Controls and Inserts and is searchable by name/group/units. Exact native instance ID is retained in the tooltip/model; duplicate names are distinguished by their displayed chain positions, without using those positions as binding keys. External targets are explicitly registry-only/non-writable. Unresolved curves retain their points and stable target and cannot write into a replacement slot.

Touch is armed independently of the displayed curve. It starts only after an owned playback generation is actually playing, using the producer's observed source-frame clock rather than a stale UI playhead. Arming Touch enables Read for that target. The slider describes the armed target, and switching the displayed curve cannot change its units or destination. Releasing holds the last written value until the release frame and returns to the captured underlying curve over 100 ms in the parameter's interpolation scale. Discrete controls return by a step. A pass is bounded to 2,044 captured points; the per-curve bound is 2,048, with 8,192 points per design and 256 stored targets per owner. Hitting a bound retains the completed legal pass or reports validation failure; no automatic thinning or continuous Write mode is implied.

Volume curves use exact project frames at the owner output, including each path's reported latency compensation. Base volume uses the existing 5 ms gain smoothing. Native insert, Pan and spatial targets use deterministic project-anchored 32-frame control segments, also split at exact stored keyframes and every relevant downstream latency/prefix boundary, followed by the existing processor smoothing. At 48 kHz the segment interval is at most 0.667 ms; this is a control-scheduling bound, not a promise of instantaneous filter/effect response. Touch captures UI gestures against the observed producer clock; it is not sample-timed hardware automation. Live seek retains the existing approximate 250 ms pre-roll/history policy; Accurate audition reconstructs from frame zero. Fresh loop restarts and offline readers share the same evaluator/rate conversion.

New frozen performances use recipe 4 and `track-automation-takes-v1`, with `project-automation-before-perform-v1`, while plugin state remains independently fixed. The recipe contains complete Track/Clip/Folder/Group/automation state; captured Perform controls still address the established source-stage controls. Hidden native automation is applied at its defined stage; a curve for an existing macro-controlled stock parameter supplies an absolute final parameter value. Track post-sum Volume composes with the distinct clip/source-stage Perform gain once at each stage. Historical recipes 1–3 retain their existing bytes, hashes and event-clock contract.

Render Selection still exports the selected clip at zero. Its new project automation is cropped/rebased from that clip's original placement, through its Track and routed Groups. The existing hosted pre-Master stem policy excludes Master effects/gain/automation; the legacy stock-only selection policy retains Master processing. Render Design and Render Take retain the complete project/frozen timeline. Export layout/masks/split roles remain independent of stereo monitoring.

Processing is bounded to 64 Tracks and 64 clips, existing per-chain limits, 16 hosted owner racks / 64 hosted slots / 24 MiB aggregate state, and the prepared alignment budget (48 Mi float samples / 192 MiB, maximum 8-second pre-Master routed path). Missing instruments/plugins, invalid layouts and hierarchy/routing cycles fail explicitly. No processors, automation points, JSON, files or opaque plugin state are created/parsed/serialized in the device callback; graph/automation work runs on the producer or preparation worker.

Native32-frame segmentation is local to native DSP and output coefficient updates. Hosted processors retain larger blocks (up to512 frames); automation must not multiply interprocess calls16-fold. The device regression requires durable events and at least12000 consumed frames during its550ms control sequence, and records PCM error/underruns. Track Pan is offered only when the chosen source/output bus equation supports it. Spatial Track panning supports Mono/Stereo into named horizontal speaker buses; coefficient ramps use5ms smoothing, and do not invent an LFE send. General multichannel spatial-object folding is not implied by first-class multichannel routing.

## Sound-preserving split correction

An unedited split is a source-history continuation. Each fragment has independent insert/rack identities and fresh independent DSP; both reconstruct the original dry source envelope and effect history from the original project position. Their audible gates hand off at the exact project-frame cut (including source-rack PDC), and only the last fragment contributes the original tail. No mutable processor or output buffer is shared. Repeated splits preserve this contract. Track-owned curves targeting copied source inserts are cloned to the new stable instance IDs, with independent point IDs and unchanged project-frame keyframes. Ordinary copy still does not inherit another source instance's automation.

Source timing, move, slip, rate, reverse, trim or fade edits deliberately establish a fresh fragment boundary and retire its continuation. Gain, pan and insert edits remain independent and retain source history. The continuation never certifies stochastic plugins as bit-reproducible; deterministic owned processors are the regression oracle. Interactive seek still has its documented bounded-history approximation; Accurate audition and offline rendering reconstruct full history.

Documents containing continuations require manifest12; other documents retain their existing manifest. The optional `splitHistory` metadata is absent from historical recipes, so existing frozen recipe/hash bytes remain unchanged. Ordinary stock and hosted multitrack outputs retain `multitrack-automation-v1` across save/reopen. Hosted outputs additionally retain the authoritative single raw float pass and its hash; the graph label does not replace raw-pass authority. Historical output labels are retained rather than upgraded.

Automation editor components are retained by document incarnation, variation and stable owner identity across unrelated disclosure/layout changes. Hiding/removing their owner finishes the active pass; replacement of the owning document rejects old callbacks without ending a new document's gesture. A numerical dialog also binds its original displayed target and point selection.
