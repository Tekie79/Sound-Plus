# Performance control state — implementation design

Written before implementation against `43f5776`. This is the bounded M2 stereo blend/macros/static-snapshot slice, not recorded motion, sampler voices or a separate engine.

- **Base and controls:** each `DesignMix` owns its unchanged base layers/racks plus a versioned performance state. The original mix and each variation/snapshot therefore retain their own assignments, macro names, values and bypass flags. Entering Perform changes a workspace preference only. Assignment and mapping start bypassed; activation is explicit.
- **Resolution:** one pure `resolvePerformance` path copies the base mix, applies absolute macro targets and then blend amplitude factors, and clears the copied control state. It never writes effective values into the base. Resolving an already resolved mix is idempotent. Live parameters, graph initialization, accurate audition, offline render and selected-layer printing consume this same result. Selection printing resolves the complete mix before isolating/rebasing the primary layer.
- **Blend:** four stable-ID slots occupy top-left, top-right, bottom-left and bottom-right. Bilinear nonnegative corner coefficients are restricted to occupied slots and normalized to unit sum of squares. A single assigned layer has weight one; zero assignments do nothing. At an unoccupied corner with zero total coefficient, occupied slots get equal-power weights. Unassigned layers stay unchanged. Weights never exceed one; coherent summation can still clip, so the master/clip indicator remain explicit. Bypass restores base levels; reset centres the pad without enabling it. Gain transitions use the existing smoothed worker-side path.
- **Ownership:** one macro writer per stable parameter key, including bypassed mappings. Blend reserves assigned-layer gain from macro assignment. Targets identify layer ID, effect ID and parameter kind, never indices or names. Missing/incompatible targets remain unresolved and do nothing. Structural parameters and linked rate/pitch are excluded. The Edit inspector and canvas gain line display effective macro values. A deliberate Gain, Balance, master-gain or mapped-effect edit explicitly unlinks only that target, even when the chosen value equals its stored base. Other mapped targets remain controlled; blend weighting remains separate. The mapping editor exposes this policy. Variation locks continue to constrain random generation, not intentional performance gestures. Generation skips macro-owned parameters.
- **Macros:** four named normalized controls, individually enabled/bypassed, with reset values. Mappings store min/max, inversion and linear/logarithmic/smooth curves. Frequencies use logarithmic interpolation by default; gain is in dB, pan is signed balance, wet is a unit fraction. Suitable filter cutoffs and delay/reverb wet controls reuse the existing stock processors; coefficient changes are smoothed on the producer worker. No additional voice or graph is created by performance controls.
- **Snapshots:** Save Snapshot stores an exact base-plus-control mix using the existing named variation history, keep/discard/A-B/save/render workflow. It creates an editable kept variation: later edits while that candidate is selected change it, as they do other variations. It does not bake and then reapply controls, and is not called a take. Print-back is still a normal committed external layer.
- **Compatibility:** designs with performance state use manifest version 2 and a new stock-DSP compatibility tag; existing readers reject them instead of ignoring audio-affecting fields. Version-1 designs load with neutral defaults and keep their sound. Atomic saves, backups, recovery and receipts remain unchanged. Derived blend amplitude is serialized only for explicitly resolved intermediate documents, with the same version gate.
- **Threading and gestures:** UI values are bounded/coalesced by the existing 25 ms parameter path. JSON, resolution, file writes and DSP graph work stay off the callback; the callback still consumes prepared PCM. Gestures use session begin/end/cancel with document/variation identity gates. One drag gives one undo step; Escape restores its starting state. Edit/Perform switching never calls transport or mutates the recipe.

The implementation report records actual tests, native screenshots, measured hardware workload and remaining qualification limits. Resolve native delivery stays an independent open manual item; no drag implementation change is planned.

## v1.1 corrections and waveform infrastructure

The v1 blend law above remains **legacy law 1** for saved manifest-2 mixes and snapshots. New mixes default to **law 2**. With 2 occupied corners, project onto their segment and use its linear coordinates. With 3, project onto their triangular convex hull and use barycentric coordinates. Normalize those nonnegative amplitudes to unit squared sum. Outside the hull, closest-point projection gives a unique continuous extension, including empty corners and edges. Zero remains no-op, one remains unity, and four retains the exact bilinear law. No pointer history participates.

Nested performance state version 1 loads as legacy law 1. Version 2 explicitly stores law 2. Any mix using the new control state requires manifest **3 / stock-perform-v2**; untouched legacy state saves as manifest 2. The **Update law** action changes only the active mix and is undoable. Original/other snapshots keep their own laws; existing durable WAVs are untouched. Older manifests cannot disguise the new law. Live, Accurate audition, snapshot, full and primary-layer rendering still share the resolver.

Escape latches a held control as cancelled until its release callback; later value events restore the UI from the model and cannot create edits. A fresh drag clears the latch. Existing identity/token gates also suppress events after document/variation switches.

`WaveformPool` replaces the Designer's unbounded result map and single pending manual scheduler, and is shared with the Library's detailed audition and file rows. It retains at most **48 sources** (at most 24 MiB of peak pairs), **96 geometries** (up to 2048 columns each), and **40 demanded assets per surface**. Selected audition, visible Perform cards, visible rows with two neighbors, and visible Edit layers are prioritized in that order. The existing reference-audition cache remains separate. One serial `WaveformCache` worker services the shared pool; paint methods never enqueue decoding or touch source files. Completion generation is observed independently by each surface. Visible cached sources are stamp-validated on that worker after five seconds; unavailable results are retried there, so reconnect can restore access.

Source identity includes ID, revision, path, size, modification stamp and inode. Cards additionally bind layer ID, selected half-open source range and reverse. A rebind clears the old geometry immediately. Immutable source peaks are reused for alias, rate, macro, gain and XY changes; geometries crop/reverse them without re-decoding. The compact renderer aggregates **every intersecting peak bin** per logical pixel column. Partial edge bins are included conservatively, so trimmed boundaries are accurate to cache resolution, not sample-exact amplitude detail. Peaks combine extrema across **all source channels**, preserving opposite-phase and nonselected-channel transients; they are explicitly an all-channel source overview before layer fades/gain/inserts/macros, not a selected-pair or output waveform.

The passive head uses `sourceAtTimeline` and `layerDuration`, including placement, source range, source clock, linked rate and reverse; it hides outside source content and when the shared transport belongs elsewhere. Source-card selection only changes selection. Return/double-click opens that stable layer in Edit. Ordinary selection/painting never plays, seeks, renders, or starts another transport.

## v1.2 selection and scheduler reliability

Selection pinning is separate from page retrieval. `pinSelection(request, pageSerial, assetId)` accepts only the currently published/requested query, names a stable identity, and does not fetch rows. An older publication of that same query can still name a selected ID outside the current prefix. The view retains that explicit cached selection without assigning its former index to another asset. A new query clears an absent UI selection without stealing audition. Library audition ownership is tracked independently, so a deliberate new selection after searching can still follow an active/pending audition. Catalog removal is an explicit state; only that recording's audition is stopped. Deleted browse IDs are compacted while the remaining pinned membership/order is retained.

The background reader serializes sequence adoption with selection pinning. If a click pins while fusion/reordering is in flight, that transaction and its annotation changes are discarded; new results are offered explicitly. Page fetches remain request-aware and page-serial-deduplicated, including re-fetching a larger page after a shorter prefix replaces it. Visible row intervals use the viewport's actual view area and half-open row bounds, with two neighbors prefetched per side.

The shared waveform pool advances the existing decoder generation when pending work becomes abandoned. Newly selected uncached work may preempt lower-priority decoding at a cooperative block boundary. Repeated same-source demands do not cancel useful work. A bounded oldest-service record spans all currently demanded keys; scheduling no longer truncates at the first 48. Every fourth ordinary admission crosses priority groups, and after three foreground admissions a still-demanded background job gets a protected admission. Abandonment still cancels it. Protected useful work finishes before another priority interruption; foreground latency during that reservation depends on the job/storage duration. This job-based fairness policy avoids indefinite background starvation without claiming an interruption bound for OS I/O.

Retention remains 48 peak sources / 96 geometries, 40 demands per surface, and one serial worker. Up to 8 selected/card sources receive retention reservations (normally one selected source plus four cards). Decoder checkpoint hooks are empty in normal production use and allow deterministic tests to observe generation cancellation between actual reads. Metrics distinguish decode attempts, validated derivative adoptions, cancellation, priority preemption and fair admissions.

Audio supervision now retains bounded lifecycle evidence: heartbeat/command/status timestamps and sequences, helper/process/play/graph generations, last device/resource state, first reason, bounded stderr, exit signal/code and supervisor action. The 5-second watchdog is unchanged. A stopped process is resumed for bounded termination/reaping. Explicit reconnect, signal exit, watchdog failure, ordinary EOF and benchmark/preview waits are reported separately. The original v1.1 restart remains an unresolved historical observation unless its cause is actually reproduced.

The v1.2 pass added no recorder. The v1.3 extension below implements the subsequent creative slice.

## v1.3 applied Perform takes

`PerformTake` holds a shared immutable recipe, bounded copy-on-write event list, source IDs/stamps/content fingerprints, exact consumed output-frame count/rate and exclusive project-frame interpolation dependency. Completed takes do not inherit later live edits. `DesignTakeSession` owns the state machine, worker preparation, intentional Undo and recovery. `TakeCapture` publishes a preallocated 8192-event array from the serial PCM producer to a checkpoint worker. The real-time callback only reads existing PCM and publishes consumption/hazard state.

Capture happens at `DesignReader` source production after input coalescing. Stop removes speculative events beyond consumed audio. `DesignGraph` replays the stored full control states at their integer project frames through the shared resolver and stock DSP, using a take-only partition-independent smoothing contract. Full-history take audition and render share this graph; static recipes preserve their old processing/version behavior. Outputs use the existing permanent WAV/receipt pipeline and ordinary external-layer print-back.

Detailed limits, identities, same-frame behavior, rate conversion, tail policy, recovery and compatibility are specified in [the take contract](PERFORMANCE_TAKES_CONTRACT.md). Actual verification is in [the v1.3 report](PERFORMANCE_MIXER_V1_3.md).
